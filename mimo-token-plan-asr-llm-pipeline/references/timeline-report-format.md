# 时间线报告格式

[English version](timeline-report-format.en.md)

当你修改时间线报告 prompt，或检查输出是否符合目标播客摘要风格时，阅读本文档。

## 目标

生成一篇可作为深度播客笔记阅读的 Markdown 报告：

- 用时间点章节说明每个时间段讲了什么
- 每个时间点下面有简洁但有信息量的段落
- “关键论据 / 金句”优先提炼具体机制、案例、数据、因果链或边界条件，不为每个窗口强凑引用
- 只有同窗存在完整独立、高信息密度的逐字原话时才标为金句
- 最后提供方便快速浏览的总览表

ASR transcript 基于分片窗口，而不是逐句时间戳。所有时间点都应视为近似窗口锚点。默认情况下，报告应基于 LLM 校对后的 `{base_name}_校对.txt`，而不是直接基于脏的 ASR 原始稿。

脚本不应该让一次 LLM 调用生成整篇长播客正文。应按批次生成时间线章节，然后校验和合并。

## 校对阶段规则

- 报告生成前应先校对 ASR transcript：补标点、断句、修正错别字、英文术语、人名和公司名。
- 校对阶段必须保留每个 `[HH:MM-HH:MM]` 窗口标签，不得合并、跳过或新增窗口。
- 校对不是摘要；不得删除实质内容、压缩观点或改写结论。
- `api-llm` 路线由脚本自动校对并保存 `{base_name}_校对.txt`。
- `ide-agent` 路线由 Agent 使用当前 IDE 模型先校对，再基于校对稿生成 `batch_*.md` 章节。
- 只有 transcript 已经人工校正或来自高质量字幕时，才允许跳过校对。

## 必需结构

```markdown
# [节目标题或根据文件名生成的标题]

> **嘉宾**：[仅在用户提供或 transcript 中明确出现时填写]
> **主播**：[仅在用户提供或 transcript 中明确出现时填写]
> **系列**：[仅在用户提供时填写]
> **时长**：约 X 小时 Y 分钟

> **转写说明**：本文基于 ASR 分片转写稿经 LLM 校对后整理。时间点来自 ASR 分片窗口，非逐句时间戳；校对阶段仅修正标点、断句、明显错别字和专有名词，不做内容压缩。

---

## 00:00-00:03 开场：[主题]

[用 2-4 个短段落解释开场内容。]

> **核心观点**：[一句硬核结论，不复述章节标题]
> **关键论据 / 金句**：论据：[同窗中的具体机制、案例、数据、因果链或边界条件] <!--依据：“同窗逐字片段”-->

## 00:03-00:06 [主题]

[用 2-5 个段落解释论点、案例、结论和上下文转折。]

> **核心观点**：[一句硬核结论]
> **关键论据 / 金句**：原话：“[同窗逐字、完整独立且高信息密度的原话]”

## 00:06-00:09 [主题]

[一个章节必须严格对应一个 transcript 窗口。]

> **核心观点**：[一句忠实概括]
> **关键论据 / 金句**：背景：[有有效语音但没有独立论证时的事实性上下文] <!--依据：“同窗逐字片段”-->

## 核心观点速览

| 时间 | 章节 | 核心观点 | 关键论据 / 金句 |
|------|------|----------|------------------|
| 00:03-00:06 | [章节标题] | [一句简洁观点] | 论据：[具体支撑] |
```

每个 batch 时间章节末尾都必须携带且只携带上述两行 blockquote 元数据。第二行四选一：`论据：... <!--依据：“同窗逐字片段”-->`、`原话：“...”`、`背景：... <!--依据：“同窗逐字片段”-->`、`无可用证据（该窗口无有效转写）`。论据与背景的依据必须逐字属于同一窗口并能具体支撑转述；最终合并器核验后逐窗转成速览表，并从时间章节正文中删除元数据。HTML 注释在渲染结果中隐藏，但保留在 Markdown 中供发布校验；不得再调用模型改写或用占位文案补表。

## 时间点规则

- 只使用 transcript 中的 `[HH:MM-HH:MM]` 窗口作为时间来源。
- 每个 transcript 窗口必须生成且只生成一个 `## HH:MM-HH:MM 主题` 章节。
- 报告正文的时间章节数量必须等于 transcript 窗口数量。
- 即使一个主题跨越多个窗口，也不要合并相邻窗口。
- 不要跳过安静、很短、拒识或噪声窗口；要创建章节并如实标注限制。短窗口仍有有效语音时使用 `背景：...`，不得误标为无证据。
- 开场窗口使用 `## 00:00-00:03 开场：主题`。不要使用没有时间点的 `## 开场`。
- 不要生成 transcript 中不存在的分钟级或秒级精度。
- 某个 ASR 窗口没有有效语音时，正文必须明确标注 `> ⚠️ 本窗口（00:24-00:27）无有效转写，无法提炼本窗口观点。`，元数据第二行必须是 `> **关键论据 / 金句**：无可用证据（该窗口无有效转写）`。不得借用相邻窗口补写本窗口。

## 分批生成规则

- 默认批大小是 6 个窗口，除非用户通过 `--timeline-batch-size` 覆盖。
- API LLM 默认最多并发处理 2 个独立批次；用 `--llm-concurrency 1` 恢复串行或规避 provider 限流。
- `separate` 模式按批次执行“校对 -> 立即生成该批摘要”，不要等待全部窗口校对完成后才开始摘要。
- 每个 batch prompt 必须列出本批要求的精确窗口，并强制要求 N 个窗口 -> N 个章节。
- batch 输出只能包含 `## HH:MM-HH:MM 主题` 章节以及每章末尾固定的两行 blockquote 元数据；不要包含报告 H1、节目元信息 block、转写说明或最终表格。
- 按标题解析返回章节。只保留 transcript 中存在的窗口，忽略幻觉生成的额外窗口。
- 如果校验发现缺失窗口，只对缺失窗口重新发起修复 prompt。
- 如果任何 transcript 窗口仍然缺失、重复、被非 transcript 时间窗口替代，或缺少合格的两行元数据，写文件前必须失败；不得用统一占位兜底。
- 正文完成后，合并器直接使用每章两行元数据生成 `## 核心观点速览`，每个时间章节对应一行；生成表格后从正文移除这两行。

## 总结方式规则

所有总结方式都必须产出同样的最终结构，并通过同样的 transcript 窗口校验。

- `ide-agent` 是未选择 LLM API 时的默认方式。Agent 读取带时间窗口的 transcript，先逐窗口校对，再每 6 个窗口生成一个 `<base_name>_agent_sections/batch_*.md` 文件，然后运行 `--manual-sections-dir` 合并和校验。
- `api-llm` 只在用户明确选择 LLM API provider，或提供 `--llm-provider` / `--llm-api-key` 时使用。默认 `separate` 模式按批次流水线校对和摘要并保存校对稿；`inline` 模式在摘要调用内部校对且不保存校对稿；`skip` 模式直接使用输入文本。
- `manual` 只作为用户要求导出 prompts 或手动粘贴模型输出时的 fallback。导出的 prompt 必须要求模型先在窗口内校对 ASR，再输出摘要章节。先使用 `--export-ide-prompts`，再使用 `--manual-sections-dir`。
- 每个 batch 输出只能包含带时间点的 `## HH:MM-HH:MM 主题` 章节和每章固定的两行 blockquote 元数据。
- 任何模式下都不要合并窗口、跳过窗口，或创建 transcript 之外的时间戳。

## 内容规则

- 每个 transcript 窗口产出一个时间点章节。47 个窗口就产出 47 个章节。
- 每个章节应自包含：讲了什么、为什么重要、用什么案例或论据支撑。
- 核心观点必须是有信息量的结论，不复述章节标题，不因窗口数量强凑观点。
- “关键论据 / 金句”优先写 `论据：... <!--依据：“同窗逐字片段”-->`，具体说明同窗中的机制、案例、数据、因果链或边界条件；逐字依据必须与转述共享具体内容，支撑不具体或无法同窗核验时不要包装成论据。
- 只有一段原话逐字存在于同一校对窗口、语义完整独立且高信息密度时，才写 `原话：“...”`。不得跨窗拼接、改写成伪原话、截成残句，或用省略号机械裁剪。
- 有有效语音但没有独立论证时，写 `背景：... <!--依据：“同窗逐字片段”-->`，只交代事实性上下文，不把寒暄、身份介绍或主持人问题包装成论据或金句。
- 只有窗口没有有效语音时，才写精确文本 `无可用证据（该窗口无有效转写）`；不得用“依据正文”“见上文”“无可用原话”等统一占位。
- 不得选择寒暄、身份介绍、主持人问题、口头填充、残句或缺少先行词的代词句作为 `论据` 或 `原话`。原话不确定时改为忠实的 `论据：...` 或 `背景：...`。
- 只在上下文高度明确时修正明显 ASR 拼写或人名错误。
- 不要编造嘉宾、主播、产品、观点、引用或缺失片段内容。
- 如果元信息不存在，省略该元信息行，不要写“未知”。

## Brief 风格

`brief` 报告风格是旧版紧凑摘要。它可以包含简短内容时间线，但不要求生成完整时间点章节，也不要求生成最终速览表。
